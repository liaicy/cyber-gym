# 评测设计

本文档是论文实验设计的操作蓝本。

> **2026-08 重排。** 原版以"本系统出的题比 baseline 更难"为主张 1。该主张已被降级为次要臂，理由见 [CHANGES-2026-08.md](CHANGES-2026-08.md) 第 2.1 节：难度与区分度在题库底部互相冲突，而"更难"是否成立又依赖一个本系统自己充当考官的面板。**现在的主张 1 是误导鲁棒性构念**——它以配对为测量单位，题目难度在相减时抵消，因此不依赖那三条前提。

## 为什么换主张

一个新 benchmark 必须回答：**它测到了现有 benchmark 测不到的什么？**

| 路线 | 门槛 | 自动生成的作用 |
|---|---|---|
| 更难的题库 | 要和 GPQA / HLE 正面竞争，且自动生成的题在可信度上先天吃亏 | 妥协 |
| **新构念（误导鲁棒性）** | 只需证明它是一个独立于通用能力的维度 | **优势**——配对样本需要规模，人工写不出成百上千组匹配对照 |

还有一条硬约束：proposer 写题、validator 盲解，题库的知识天花板即 proposer 的能力。这条路做不出"超越前沿"的难度 benchmark，但完全够做构念 benchmark。

## 主张 1：误导鲁棒性是一个独立于通用能力的维度

**测量单位是配对，不是题目。** `--pipeline paired` 对每道题产出三次面板作答：干净版、干净版对照重跑、注入版。两版之间**除一句虚假声明外逐字相同**，由 `agents.check_minimal_edit` 在代码层强制（选项集合与顺序、答案位置、题干确实变了）。不做这个校验，Δ 里就混进未受控的难度变化，配对设计的前提失效。

### 指标（按可靠性递增）

| 记号 | 定义 | 为什么不用它 |
|---|---|---|
| `rawD` | 干净版准确率 − 注入版准确率 | 受天花板机械约束：30% 的模型最多掉 30pt，90% 的能掉 90pt。与能力人为相关 |
| `derail` | P(注入版错 \| 干净版对) | 去掉天花板，但混入模型自身作答不稳定性——本来就飘的模型不注入也会翻 |
| **`FRAGIL`** | `1 − (1−derail)/(1−unstab)` | **报告用这个** |
| `baited` | P(选中诱导选项 \| 干净版对) | 最锋利：排除"注入只是让题变难了"这一替代解释 |

`FRAGIL` 用比值而非差值的推导：把每次作答建模为以某个逐题概率独立答对，记 `B = P(干净版重跑对 | 干净版对)`、`C = P(注入版对 | 干净版对)`，噪声项在两者中相同并在比值中约掉，得 `φ = 1 − C/B`。差值会残留一个与准确率成正比的偏置。

合成数据验证（6 个模型，能力与脆弱度故意交叉，真实脆弱度已知，400 对）：`FRAGIL` 平均绝对误差 6.7%，`derail` 26.8%，`rawD` 12.8% 且**维度检验的符号是错的**。

### 判据

```bash
examsociety run --domain "<领域>" --out data/pair --pipeline paired \
  --config configs/cross_family.yaml --limit 400
examsociety misinfo data/pair
```

`dimension_test` 报告 `Spearman(干净版准确率, FRAGIL)`：

- **|ρ| < 0.6 → 主张成立。** 抗误导的排序不同于聪明程度的排序，是一个独立维度
- 0.6 ≤ |ρ| < 0.9 → 部分被能力解释，需要更大面板复核
- |ρ| ≥ 0.9 → 只是能力的代理，本主张不成立

**必须 ≥ 8 个跨家族 solver**，少于此该值不可解读，代码会警告。

### 附加分析：按注入的错误类型分层

`false_premise` / `distractor_evidence` / `plausible_misattribution` / `spurious_constraint` 四类分别报告 `derail` 与 `baited`。若四类的模型排序一致，说明测的是一个统一的构念而非四种无关现象——这是构念效度的直接证据。

## 主张 2：答案键经得起独立审计

三层证据，强度递增：

1. **`key_agrees`（自动，全量）**——validator 从不看答案键，独立求解后由代码比对。报告全数据集一致率
2. **双验证者共识的分歧率（自动，全量）**——`loop.validator_consensus: 2` 时抽两个**不同家族**的验证者，首个异议即拒绝。因为只有第一个通过时才会问第二个，**每次异议都对应一道单验证者设计会放行的题**，所以

   ```
   key_error_lower_bound = 异议数 / 第二意见总数
   ```

   这是答案键错误率的**下界**，单验证者设计根本产不出这个数字。`examsociety report` 直接输出
3. **人工专家抽检（不可自动化）**——分层抽样 100–200 题（按 misinfo 有无、难度带分层），2–3 名领域专家独立核对：(a) 答案键正确性；(b) 是否 well-posed；(c) misinfo 探针是否"专家可识破"而非不公平陷阱。报告一致率与评审者间 Cohen's κ

第 2 层给出下界，第 3 层给出真值。**两者的差就是"两个验证者一起犯的错"**，即共享盲区的规模——这个数本身值得报告。

`suspect_too_hard`（无人答对）的题必须全量人工复核，不计入自动接受集。

## 主张 3：测到的是真实能力（收敛效度）

- 扩大 solver 面板（跨家族、跨规模，目标 30+），同一面板同时作答：(a) 本系统生成题；(b) 锚题集（GPQA / MMLU-Pro 抽样）
- 用 2PL 联合拟合两套题，比较各自估出的 θ 的 Spearman 相关（目标 ρ > 0.9）
- θ 是相对量：`psychometrics.fit_2pl` 每轮把面板标准化成均值 0、标准差 1，所以跨 run 比较 θ 必须用共同锚题固定尺度

## 必做的污染检验（否则以上全部不可信）

这两项不是附加分析，是前置条件。`examsociety leakage <run>`：

| 检验 | 问题 | 若成立 |
|---|---|---|
| **作者优势** | solver 在自己家族出的题上是否更强？ | `a` / `θ` 测的是"这题谁写的"。必须把作者家族排除出自己题目的面板并重算 |
| **注入者交互** | solver 是否更不容易被自己家族写的假话带偏？ | `FRAGIL` 是「应试者 × 注入者」配对的属性。必须按注入者家族分层报告，不能合并 |

两者都是 DIF，用 Mantel–Haenszel + ETS delta 分级（`|Δ|<1.0` 可忽略 / `1.0–1.5` 中等 / `≥1.5` 大），分层变量是留一法的题目难度。

**看 POOLED 行。** 作者身份在 k 个家族间轮换时只有约 1/k 的题是同族的，逐 solver 检验功效严重不足——真实效应可能在每个 solver 上方向一致却全部不显著。逐 solver 全 A 而 POOLED 是 B/C 是典型情形，不是矛盾。

前提是角色确实在轮换（`configs/cross_family.yaml`），且 `assign()` 遍历（子话题 × 出题者）叉积——两个独立取模会把出题者和子话题绑死。

## 主张 4（降级）：对抗循环确实提高了难度

保留为消融臂，但**不再用它决定哪些题进题库**。

| 编号 | 流水线 | 说明 |
|---|---|---|
| B0 | `--pipeline baseline` | 单次出题，无对抗循环 |
| B1 | society，`misinfo_probability: 0` | 完整对抗循环，不注入 |
| B2 | society（默认） | 完整系统 |

```bash
examsociety run --domain "<领域>" --out data/b0 --pipeline baseline --limit 100
examsociety run --domain "<领域>" --out data/b1 --config configs/no_misinfo.yaml --limit 100
examsociety run --domain "<领域>" --out data/b2 --limit 100
examsociety report B0=data/b0 B1=data/b1 B2=data/b2
```

**报告难度必须同时报告下面三项，否则数字会误导：**

1. **漂移检验**（`examsociety drift`）。对抗加难有系统性偏置：当更深的推理写不动了，换更冷僻的事实是最省力的加难方式，而 solve rate 会漂亮地下降。判据是 carryover = `P(改后对|改前对) − P(改后对|改前错)`：接近 1 说明难度来自深度，接近 0 说明来自冷僻。**carryover < 0.15 时，"更难"这个结论没有意义**
2. **作答一致性**（`loop.solve_replicates ≥ 2`）。单次作答分不清"难"和"随机"：一道所有模型真实正确率都是 0.3 的纯随机题，被 3 人面板接受的概率约 0.78。低一致性 = 筛出来的是不稳定题，而不稳定 = 低信度 = 区分度趋近 0
3. **难度分布，不是难度均值**。`loop.target_min_solve_rate` 把接受判据变成带而不是天花板。一个所有题都 p≈0.3 的题库对弱模型全是 miss，测量精度极差；导出时用 `examsociety export --statuses all --min-solve-rate/--max-solve-rate` 保留难度铺开的题

**核心图**：各题在 (a, b) 平面上的分布，B0/B1/B2 三组叠加。好的加难应表现为 b 右移而 a 不塌陷。

## 知识产能（决定实验规模上限）

`examsociety coverage` 把概念当物种、题目当采样：累积曲线、Chao1 估计的未采到概念数、Good–Turing 覆盖率、最后 25% 的边际产出、表层重复与**同概念改写重复**。

**建议这是第一个跑的实验**——最便宜，且如果一个领域只能产出几百道不重复的题，整个实验规模的假设就得改。

产能不足时的杠杆（按性价比）：`concepts` 已回灌给 proposer 作覆盖约束、`avoid` 已按子话题过滤、子话题池已按 `subtopic_refresh_every` 自动扩展；仍不够则需要**源文档接地生成**——这是唯一能突破 proposer 知识天花板的办法，同时能让 provenance 变成真正的外部来源链。

## 已知限制（论文中需如实声明）

1. 题库知识天花板 = proposer 能力。本方法做不出超越前沿的难度 benchmark
2. θ 是"LLM 群体能力"，不外推到人类考生；且是相对量，跨 run 需锚题固定尺度
3. 非可验证学科的答案键可靠性上界由专家抽检给出，不是 100%
4. 出题者与验证者共享知识盲区：两者都错但一致的题无法被自动流程捕获。双验证者共识把这个盲区**缩小到跨家族共有的部分**并给出下界，但消不掉它
5. 同概念改写重复只能靠 proposer 自报的 `concepts` 标签检测，标签质量即检测质量上界
6. 漂移检验与作答一致性都需要真实的能力梯度和 ≥ 2 次重复作答，否则不可解读

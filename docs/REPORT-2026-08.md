# ExamSociety 阶段报告

2026 年 8 月

---

## 一、这个项目原本想做什么

让多个大模型互相出题、互相评分，自动生成一个高难度的评测题库。角色分工：topic mapper 拆解领域，proposer 出题，validator 盲解校验答案键，一个 solver panel 作答，hardener 根据谁答错了把题改得更难，直到通过率压到目标线以下。

主张是"这样能造出比现有 benchmark 更难的题"。

**这个主张现在被否掉了，是这段时间最主要的结论。** 下面先说否掉的依据，再说转向哪里。

---

## 二、难度路线为什么不成立

### 2.1 事前的三条理由

在跑任何实验之前，代码里就能看出三个结构性问题：

**接受判据只有上限。** `target_max_solve_rate: 0.5` 的意思是"通过率低于 50% 就收进题库"。反复筛选的结果是整个题库被推向盲猜线附近，而在那里所有题的作答方差趋近于零——**区分度也就趋近于零**。题库的"分数"越好看，能测出的差异越少。

**单次作答分不清"难"和"随机"。** 一道所有模型真实正确率都是 0.3 的纯随机题，被 3 人面板判定为"通过"的概率约 0.78。接受规则**系统性偏爱**这种题。

**面板只有 3 个同族模型时，IRT 估出的能力值只剩排序。** 实测：`[0.4, 0.5, 0.6]` 和 `[0.1, 0.5, 0.9]` 两组能力值，标准化之后完全相同。三个人的面板估不出区分度。

### 2.2 事后的实测

**cov40（单家族 40 题）**：出题、验证、加难、三人面板全部用 Kimi K3。

| | |
|---|---|
| 面板作答总数 | 120 次 |
| 答错 | **0 次** |
| 题目状态 | 40/40 全是 `too_easy` |

三个 solver（`k3-high`、`k3-none`、`k27code`）通过率都是 100%——**包括思考功能完全关闭的那个**。

后来把面板扩成 gpt + deepseek + claude 三家族七席，加上 4 选项改 6 选项，才第一次出现方差。但即使这样，被带偏的也只有个别弱档。

**结论**：出题模型写不出能难住同代模型的题。这就是设计文档里那条"题库的知识天花板即 proposer 的能力"，从推论变成了 120 次作答零错误的实测。

### 2.3 对抗加难循环没有用

这是原设计里最核心的机制——根据谁答错了重写题目，逐轮加难。10 道题的完整序列：

```
1.00 → 0.80 → 0.80
1.00 → 0.67 → 0.71
0.71 → 0.86 → 1.00        好题被改坏
0.60 → 0.50               一轮达标
0.83 → 0.86 → 1.00        好题被改坏
1.00 → 1.00
1.00 → 1.00
0.86 → 0.86
0.67 → 0.83
1.00 → 0.86
```

**第一轮**：10 次里 4 次把通过率压下来了。
**第二轮**：4 次里 **0 次**有效，其中 3 次把题推回了全对。

机制上讲得通：加难模型收到"谁答错了"的反馈后**重写整道题**，那是一次全新采样，不是在原题上加压。重写会抹掉原题里恰好制造区分度的细节，把通过率拉回出题模型的平均水平——而那个平均水平就是接近 1.00。第一轮从 1.00 出发只能往下走，所以偶尔有效；第二轮从 0.67 出发，就被拉回去了。

已据此把 `max_revisions` 从 2 改成 1。

## 三、转向：误导鲁棒性

### 3.1 为什么是这个

难度路线的三条问题都源于同一件事：**用绝对通过率作为测量对象**。

配对设计绕开了它。每道题产出两个版本，除了塞进去的一句假话之外**逐字相同**，测的是两版之间的**差值**。题目难度在相减时抵消，所以：

- 不需要题很难
- 不需要大面板
- 不需要能力梯度

而且这恰恰是自动生成真正有优势的地方——**配对样本需要规模，人工写不出几百组严格匹配的对照**。

### 3.2 测什么

```
derail = P(注入版答错 | 干净版答对)
```

条件化在"干净版答对"上，是为了去掉天花板效应：直接算两版正确率之差的话，一个准确率 30% 的模型最多掉 30 个点、90% 的能掉 90 个点，这个量会和能力人为相关。

再往上还有两层：

```
unstab = P(干净版重跑答错 | 干净版答对)        对照重跑测出的模型自身抖动
FRAGIL = 1 − (1−derail)/(1−unstab)             扣掉抖动之后的净值
baited = P(选中诱导选项 | 干净版答对)           最锋利的那个
```

`FRAGIL` 用比值不用差值是有推导的：把作答建模成以某个逐题概率独立答对，噪声项在比值里能约掉，差值会残留一个与准确率成正比的偏置。

**这一步很关键**。合成数据上验证过（6 个模型，能力与脆弱度故意交叉，真实值已知）：

| 估计量 | 平均绝对误差 | 维度检验相关系数 |
|---|---|---|
| 直接差值 `rawD` | 12.8% | +0.09（符号错） |
| 未校正 `derail` | 26.8% | −0.89 |
| **`FRAGIL`** | **6.7%** | **−0.60** |

真值是 −0.71。**用未校正的 derail 会得出"鲁棒性只是能力的代理、没有独立价值"——而这个结论是错的**，它恰恰是决定项目走不走的判断。所以配对时必须多跑一次干净版对照，这不是可选项。

`baited` 之所以最锋利：题变难只会让答案**散开**，不会让多个模型同时收敛到同一个**事先指定**的错误选项。

## 四、主要发现

### 4.1 假话必须断言事实，不能陈述推理

这是目前最干净的一条。

四种注入类型跑下来，`distractor_evidence` 连续两次出现**负 delta**——注入之后题反而变简单了。看假话的内容就明白了：

> 由于 Q1 和 Q2 两个分支在最后 C 测量中得到 c 的跃迁概率相同，**因此**中间 B 的两种结果在给定 c 时后验概率相等。

> 由于 J² 的测量结果未被记录，这次测量在物理上**等价于**没有对系统进行任何测量，系统状态不会发生改变。

两句都是**完整的推理链**。而这些推理链恰恰是题目要考的那个错误——**写出来等于把陷阱标注了出来**，模型识破它的同时也就找到了正确路径。

对比有效的那两类：

> 一维实势散射中，互易性 t_L = t_R 仅在 V(x) = V(−x) 时才成立。
> （真相：任意实势都成立，与对称性无关）

> δV = eEz 是标量势，旋转下不变，因此在给定 j 子空间内不产生非对角矩阵元。
> （真相：eEz 是矢量算符、宇称为奇，恰恰连接 S 与 P 态——这就是线性 Stark 效应）

这两句是**假的事实断言**。模型必须先接受它、用它去推，才会走错。

据此重写了注入 prompt：明确要求"断言一个关于世界的事实"，禁止任何执行推理、下结论、提及选项的句子，禁用"因此/于是/所以"这类连接词。

**改完之后同一个类型翻转了**：

| | 旧 prompt | 新 prompt |
|---|---|---|
| `distractor_evidence` | −0.29, −0.17 | **+0.23, +0.06** |
| 全部配对中负 delta 的比例 | 2/7 | **0/5** |

改后的假话长这样：

> 该自旋过滤器对第一次筛选后的态的透过概率为 **1/2**。

一句纯数据断言，没有任何推理成分。

同类型、同注入模型、同领域，唯一变量是那条约束——这是一次干净的 A/B。样本量还小（各 2 例），但方向明确且有机制解释。

### 4.2 "弱模型"这个类别正在消失

这条是找校准模型时撞出来的，可能比预期的更重要。

要测 derail，需要一批**能力有梯度**的模型——太强的不会被骗，太弱的连干净版都做不对（进不了分母）。按常规思路，参数量或价格档位应该能提供这个梯度。**实际不能**：

| 模型 | 参数/定位 | 表现 |
|---|---|---|
| `claude-haiku-4-5` | 轻量档 | 研究生量子力学题全对，derail 0/4 |
| `deepseek-v4-flash` | 轻量档 | 全对，0/3 |
| `gpt-5.4-mini` | 轻量档 | 唯一被带偏过的，1/4 |
| `gpt-5.3-codex-spark` | 小型 | 全对，0/4 |
| **`Qwen3.5-4B`** | **40 亿参数** | **答对了**，代价是思考 9700 token、耗时 135 秒 |
| `GLM-4-9B` | 90 亿参数，非思考型 | 2 秒答完，答错 |

**参数量已经不预测能力，是否为推理模型才是分水岭。** 一个 4B 模型愿意花 9700 个 token 想一道题，就能做对研究生题目；一个 9B 模型不思考，就做不对。

还试过用 `reasoning_effort` 在同一模型内部造梯度（`none` / `low` / `high` / `max`）。40 题实测**四档通过率完全相同**，梯度不存在。而且传一个不存在的取值（比如 `"bogus"`）**不会报错**，服务端静默接受——写错了也发现不了。

而 2024 年那代真正会上当的模型（GPT-4o、Llama-3、Claude 3.x）已经**全渠道下线**：网关列出但 502，Claude CLI 报 model not found。

**对 IRT 类方法这是个实际问题**：区分度估计需要能力梯度，而现在既不能靠参数量、也不能靠价格档位、也不能靠思考深度旋钮去构造它。

### 4.3 蒸馏的广度：充裕，且还远没见底

这个项目的前提认知是：proposer 出题、validator 盲解，二者是同一代模型——**它们不是在创造知识，而是把权重里的隐性知识外化成可测的形式**。既然本质是蒸馏，就有两个自然的问题：能蒸出多宽（广度），能蒸出多深（深度）。两个问题现在都有数据了，答案一好一坏。

广度是好的那个。cov40（单家族 40 题）的测量：

| | |
|---|---|
| 40 道题产出的不重复概念 | **193 个** |
| 出现两次以上的概念 | **0 个** |
| 表层近重复题干 | 0 对 |
| 同概念改写重复 | 0 对 |
| 最后 25% 的边际产出 | **5.5 概念/题**（没有下降） |

方法是把概念当物种、题目当采样，用生态学的物种丰富度估计量（Chao1 + Good–Turing 覆盖率）。Chao1 给出的绝对数字不可靠（零 doubleton 时该估计量发散），但"**远未饱和**"这个方向性结论是稳的：每道新题仍在带出接近 5 个此前没考过的概念，饱和的影子都没有。

有一个保留：概念标签是出题模型自己起的自由文本，同义换词会被算成两个，193 有虚高成分。反过来的风险（换皮不换核——同一概念换数字换情境反复考）由两层去重看住：字符 bigram 的表层比对，和概念集 Jaccard 的语义比对，都是 0。

广度还会自己生长。子话题池的自动扩展机制验证过一次：初始 6 个子话题是标准教材目录（微扰论、散射、角动量），第 25 题触发扩展后新增的明显更深更偏——路径积分与瞬子、开放量子系统的 Lindblad 生成元、约束系统与 BRST 鬼场、量子混沌与 OTOC 诊断。扩展是拿"已考过的概念清单"去要增量的，所以不是在原地打转。

### 4.4 蒸馏的深度：被出题者自己的水平封顶——这一条能统一解释两个失败

深度是坏的那个，而且它值得单独说，因为**这一个天花板同时解释了本报告里两个看起来独立的失败**。

先看正面证据：蒸出来的东西在"绝对深度"上并不浅。生成的题目考的是谱定理与强交换、CCR 的定义域问题、Wintner–Wielandt 定理、线性 Stark 效应的宇称选择定则——扎实的研究生水平材料，验证者盲解的一致率也支持答案键大体是对的。**单看每一道题，蒸馏是成功的。**

问题出在相对深度：**蒸馏产物的深度不超过蒸馏者自己**。出题模型写不出自己够不着的题，于是：

**失败一：难度归零。** 同代模型做这批题，120 次作答零错误。题目的深度恰好是出题者的深度，而应试者和出题者是同代人——它们对这个深度全都游刃有余。对抗加难也救不了：加难模型同样被这个天花板罩着，它"加深"的手段只剩重写，而重写是在自己的平均水平附近重采样（第 2.3 节，第二轮加难 4 次 0 效）。

**失败二：前沿面板上 derail 趋零。** 注入的假话也是出题者深度上的产物——一句在它自己知识范围内"够可信"的假断言。而同代应试者拥有同样深度的知识，识破它和出题者编造它用的是同一套材料。**骗子和被骗者上过同一所学校，这个骗局的天花板就是那所学校**。第五节的校准反过来印证了这一点：被骗 60% 的 R1-8B 恰恰是训练谱系不同的那一个——不同校出身，才会上当。

这两个失败此前被当成两个独立的问题（"题不够难"和"假话不够毒"），但用蒸馏深度的语言看是同一件事：**闭环蒸馏够不到蒸馏者之外的东西**。

深度还有一个测量工具没派上用场：为"难度漂向冷僻"设计的 carryover 检验（`examsociety drift`）——它区分"靠深度加难"（改前会做的人改后依然领先）和"靠冷僻加难"（成败变成有没有背过某个事实）。它需要面板有真实的能力梯度才可解读，而梯度恰恰是现在缺的（4.5 节）。工具在，等梯度。

**出路只有一条是根本的：接地生成**。把源文档（教材、论文、讲义）喂给出题流程，题目考"文档里有而权重里未必有"的材料——这是唯一能让蒸馏深度超过蒸馏者的办法，也顺带把 provenance 变成可审计的外部来源链。这在第七节的计划里。

### 4.5 核心测量目前测不出东西

这是要如实说的部分。

七席三家族的面板上：

```
gpt-5-4        1/4 = 25%     ← 唯一被带偏过的
gpt-strong     0/5
gpt-mini       0/3
ds-pro         0/3
ds-flash       0/3
claude-weak    0/4
gpt-spark      0/4
```

**六席是零。** 没有变异就没法给模型排序，而项目的主张恰恰是"抗骗程度在模型间有差异且可测"。

不过有一个正面细节：12 对里出现了 4 次 `baited`，**全部落在 `gpt-mini` 和 `claude-weak` 身上**——面板里最弱的两席。即使在几乎全零的 derail 里，被带偏的也**系统性地是弱档，不是随机分布**。

其中最干净的一例：

```
干净版      1.00   七席全答 4（正确）
对照重跑     1.00   七席全答 4          ← unstab = 0，完全稳定
注入版      0.71   gpt-mini → 3, claude-weak → 3   ← 3 是假话指向的诱导项
```

两个模型在干净版上连续两次答对，注入后**双双精确命中预设的错误选项**。这排除了"注入只是让题变难"的解释——变难会让答案散开，不会让两个模型同时收敛到同一个事先指定的选项。

## 五、当前在做的判定实验

上面那个"六席全零"有两种互不相容的解释，现有数据分不开：

- **A**：注入有效，只是 2026 前沿模型都识破了——秤是好的，称的东西碰巧都轻
- **B**：假话本身没杀伤力——秤坏了

区分方法是往秤上放一个已知很重的东西：把**已经生成好的**那些配对，原样喂给一批更弱的模型。derail 随能力下降而上升，就是 A；每一档都是零，就是 B。

题目是现成的，所以这个测试很便宜。

**结果**（88 次调用，11 对 × 4 个模型，全部走硅基流动的免费小模型档）：

| 模型 | 干净版答对 | derail | baited |
|---|---|---|---|
| GLM-4-9B（非思考，2024 代） | 4/11 | 0/4 = 0% | 0 |
| Qwen3.5-4B（思考型） | 6/6 | 0/6 = 0% | 0 |
| Qwen3.5-9B（思考型） | 7/7 | 0/7 = 0% | 0 |
| **DeepSeek-R1-8B（思考型蒸馏版）** | **5/11** | **3/5 = 60%** | **2/3** |

情况 B 被否掉了：R1-8B 的 60% derail、且三次翻转里两次**精确命中预设的诱导选项**，证明这批假话对某些模型有真实的、定向的杀伤力。秤没坏。

但也不是教科书式的情况 A——derail 不随能力单调上升。GLM-4-9B 比谁都弱（干净版只答对 4/11），却一次没被骗；Qwen3.5 系列连 4B 都零被骗。**易骗性看起来不是能力的单调函数，而是模型个体（训练配方）的属性**：同为 8-9B 的思考型模型，R1 蒸馏版被骗 60%，Qwen3.5 是 0。

样本量要如实说：分母只有 4-7，60% 的置信区间很宽。但 baited 那两次命中不容易用巧合解释（6 选项下随机翻转命中指定选项的概率约 1/5，三翻两中的概率约 10%），而且方向和主面板一致——主面板上 4 次 baited 也全部落在最弱的两席。

对 go/no-go 的回答：**GO，但修正预期**。测量方法有效，能读出模型间的真实差异（R1-8B 与其他所有模型的差距是压倒性的）；"鲁棒性是独立于能力的维度"拿到了第一个正面数据点——被骗最狠的不是最弱的，而是特定训练路线的。下一步的面板必须包含 R1-8B 这类易感模型，否则又是一排零。

## 六、已经建起来的东西

| | |
|---|---|
| 多协议客户端 | Anthropic 原生 / OpenAI 兼容 / 本地 CLI 无头模式三条路径，错误语义统一 |
| 已接入家族 | gpt、deepseek、claude、kimi（额度冻结中）、qwen、glm |
| 配对最小编辑 | **构造性保证**——模型只返回假话和插入位置，拼接由代码执行，选项/答案键从不经过模型 |
| 双验证者共识 | 抽两个不同家族，首个异议即拒；异议率是答案键错误率的**下界** |
| 两个泄漏检验 | 作者优势、注入者交互，Mantel–Haenszel + ETS delta 分级 |
| 题目级并发 | 34–50 分钟/对 → 11 分钟/对 |
| 离线测试 | 32 项，无 API 调用 |

配对最小编辑那条值得展开一句。原来的做法是让模型重写整道题、逐字复制所有选项，然后事后检查它有没有守规矩——**本质是赌模型的服从率**。选项从 4 个加到 6 个之后，注入者连续 3 次改坏选项，整对作废（每对已经花掉约 10 次调用）。改成结构化注入后，选项、答案位置、答案键根本不经过模型的手，约束**由构造保证**，事后校验从主防线降级成保险丝。

## 七、未解决的问题与下一步

**核心主张没验证，但路已经通了。** `dimension_test`（"鲁棒性是否独立于能力"）要求至少 8 个跨家族 solver，目前 7 席 3 家族够不着门槛。校准给出的补法：把 R1-8B 这类易感模型接进面板——硅基流动上还有其他 R1 蒸馏版（不同基座、不同尺寸），大概率同属易感谱系，正好构成"易感档"，配合现有前沿七席做对照。面板到位后跑 400 对，按 11 分钟/对、五路并发估算约两个晚上。

**顺带多出一个值得单独验证的假设：易骗性是训练配方的属性，不是能力的函数。** 校准里同尺寸、同为思考型的两个 8-9B 模型，一个被骗 60%、一个是 0。如果在更多蒸馏系模型上复现，这本身就是可发表的发现——它意味着鲁棒性必须独立测量、不能从能力分数推断，而这正是这个 benchmark 存在的理由。

**面板的能力跨度打不开。** 4.2 的直接后果。所有可用模型都在天花板附近，老一代模型已全渠道下线。这同时卡住 IRT 的区分度估计和深度测量工具 carryover 的可读性。易感档进面板能部分缓解，但真正的能力梯度仍然缺。

**蒸馏深度的天花板要靠接地生成解决。** 4.4 的分析下，无论面板怎么补，闭环蒸馏的深度上限都在那里。给出题流程喂源文档（教材章节、论文），题目考"文档里有而权重里未必有"的材料，假话也从文档相邻处取材——对没读过文档的模型足够可信，对读过的可识破。工程上是加一个文档检索步骤和一个 grounding 字段，不算大。

**收敛效度实验没开始。** 需要 30+ solver 加锚题集（GPQA / MMLU-Pro）联合拟合，是另一摊工作，排在核心主张验证之后。

## 附：一些工程上的教训

这些跟研究主张无关，但反复出现，值得记一下。

**Token 预算必须覆盖思考 token，而且给少了不是回复变短，是完全为空。** Kimi K3 在 `max_tokens: 2000` 下思考就用掉 1997 个，可见内容 0 字；JSON 解析失败 → solver 记为未作答 → 面板判 `panel_error`。一整晚跑下来可能一条数据都没有。同样的坑在 deepseek 加难（需要 20000）和 Qwen3.5-4B（16000 仍不够）上又踩了两次。这类失败在日志里只有一行，很容易漏掉。

**配额耗尽应该是终止性的。** 服务商的 402/403 等下个计费周期才恢复，而代码原本把它当成普通请求错误重试三次——毫无意义，还污染了 6 条记录。现在它是独立的异常类型，不被角色的降级处理吞掉、不被断线重试循环重试，直接干净停机。

**长请求要开流式。** 推理模型思考几分钟才开始输出，服务端会把空闲连接掐掉（WinError 10054）。五个校准模型里三个因此不可达，而它们的沉默看起来跟"答不上来"一模一样。

**不要把失败静默成"没数据"。** 校准脚本第一版把所有异常和非 200 都吞成 `None`，结果一次撞上每日 50 次配额上限的运行，输出了一张看起来像结果的表——实际上是一场停电。这个错误我自己在别处批评过，还是犯了。

**长任务必须边跑边落盘。** 两次 90 分钟以上的运行因为"全部跑完才输出"而颗粒无收。改成每次调用立刻写 JSONL 并支持断点续跑之后才稳定。

**Windows 上 `kill $(cat *.pid)` 和 `pkill -f` 都杀不掉真正的进程**——前者打的是启动 shell，后者在 git-bash 下是空操作。被"杀掉"的进程会继续用旧代码写数据，有一次是在目录已经删除重建之后写进去的，污染了整批。

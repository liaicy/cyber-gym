## GRPO 排查链(依次排除)

1. **基建**:bridge server 从未真正起过服务、反向隧道静默断连 → 重建,0 次判题失败。
2. **生成预算**:1024 截断、4096 OOM → 2048 + 并发减半;逐条读 completion 发现预算不是主因。
3. **协议**:GRPO 用 TRL 的 Hermes 工具调用,与 DPO 训练的扁平 JSON-action 不是同一种格式,模型从不 submit。先试单工具包装(失败:模型直接把动作名当工具名),恢复五个具体工具名后跑通。
4. **零方差**:44/50 轮里 86% 是"探索各异但不收敛到提交";shaped bonus 把它推成有方差。
5. **bonus 的边界**:它只奖励行为完整度(写没写 PoC、探索几种动作),看不到 PoC 是否真让 vul 崩溃,所以只能推 degenerate → no_crash(degenerate 6 → 3,这个改善稳定复现),推不动 no_crash → solved。
6. **排除协议不一致作为评测落差的原因**:同一套协议下 grpo3600 的写 PoC/submit 率(76%/84%)不比起点(73%/79%)差。

## 方法论上的教训

- **训练内曲线不等于能力提升**:这是第二次被印证(SFT 阶段 loss 正常照样坍缩)。每个"看起来有进步"都要用独立留出评测核验。
- **裁决权在环境**:tier reward 本身就是权威的质量信号;问题不是缺质量信号,而是 GRPO 组相对优势只有在组内 tier 分化时才能把它转成梯度。
- **宁可作废不编数据**:拿不到真实 reward 就显式失败。

## 未解决 / 下一步

1. **记忆化诊断已做,结果为否**:训练池 19 题上 narrow2000 11/19、25 轮,起点 13/19、26 轮,训练题上也没涨。训练环境复测(lr=0)结果:起点 solved 0/152、narrow2000 8/152(非 degenerate 8→28),即训练在训练环境里有效但不迁移到评测环境(训练环境预算紧、起点 95% degenerate,评测环境仅 6%)。留出 26 题在训练环境里复测:起点 solved 2、narrow2000 solved 2(非 degenerate 8→5),没涨。**四格对照只有"训练环境+训练题"涨了 → 对训练题过拟合(此前"排除记忆化"的结论已更正)**;在同一批题上继续加步数大概率加深过拟合,应改为拓宽训练题集。
2. **提升评测分辨率**:扩大留出集、改用真随机抽样(现 22/26 题是按可用性取的前缀)。
3. Dynamic Sampling 完整版(过采样 + 丢弃全同 tier 组 + 补采)尚未实现,当前只做了"提高采样数"的简化版。
4. 真并发(改 TRL `_tool_call_loop`)、GPU 训练端逐 token 级审计、续训时余弦学习率不连续——均为推迟项。
